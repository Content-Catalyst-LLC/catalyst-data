# Catalyst Data v2.2.0 — External Source Adapter Framework & WordPress Integration Foundation

v2.2.0 turns the existing governed connector engine into a reusable external-source integration surface and replaces the WordPress “Demo” identity with a production-oriented public data integration.

## External source adapters

The new adapter SDK registers source capabilities separately from connector definitions. Generic HTTP JSON and CSV adapters support none/page/offset/cursor pagination, bounded page runs, conditional requests using ETag and Last-Modified state, checkpoints, adapter run/page audit records, and source-adapter lineage on imported canonical records. Adapter ingestion still terminates in the existing connector service, so payload snapshots, quarantine, reconciliation, provenance, review, and workspace boundaries are preserved.

Adapter configuration is non-secret. Authentication remains governed by connector environment-variable references; inline authorization headers or token-like query parameters are rejected.

## WordPress integration

`dist/sustainable-catalyst-data.zip` is now the primary WordPress package. It provides a Settings → Catalyst Data connection screen, public API health diagnostics, bounded/cached server-side reads through `wp_safe_remote_get`, same-origin WordPress REST proxy routes, and the shortcodes `[sustainable_catalyst_data]`, `[catalyst_data_embed]`, and `[catalyst_data_status]`.

The plugin does not accept or persist PostgreSQL connection URLs or private Catalyst Data bearer tokens. WordPress consumes only the public Catalyst Data HTTP surface.

## Persistence and compatibility

Migration 015 adds adapter bindings, state, runs, pages, and operational status while preserving the PostgreSQL/SQLite abstraction introduced in v2.1.0. The legacy `catalyst-data-demo` source remains in-tree for browser-contract compatibility tests but is no longer the primary installable plugin.
