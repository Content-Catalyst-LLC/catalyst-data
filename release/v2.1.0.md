# Catalyst Data v2.1.0

## PostgreSQL Production Persistence & Storage Abstraction

Catalyst Data v2.1.0 establishes a production database path without replacing the local-first architecture. PostgreSQL is now the supported production persistence backend; SQLite remains supported for development, testing, offline operation, recovery, and portable evidence repositories.

### Added

- Backend-aware database target resolution with `DATABASE_URL` support and credential-safe status identities.
- PostgreSQL runtime compatibility for Catalyst qmark parameters, SQLite transaction syntax, current timestamps, JSON extraction, and idempotent insert semantics.
- PostgreSQL-safe transaction and `lastrowid` behavior for the existing importer, connector, repository, analysis, Workspace, API, and platform services.
- Migration 014 for storage-backend metadata and storage-migration event history.
- Generated PostgreSQL baseline schema built from the complete canonical migration set.
- PostgreSQL trigger equivalents for append-only tables, default Workspace governance, and upstream analysis invalidation.
- Transactional `storage-migrate-postgres` command for promoting an existing SQLite repository while preserving repository identity, explicit IDs, governance state, and sequence positions.
- PostgreSQL-aware health, operational benchmark, and security-audit reporting.
- PostgreSQL package resources and CI coverage using a live PostgreSQL service when available.
- Deterministic canonical URI validation independent of optional `jsonschema` format extras, with explicit RFC 3986 validator packaging.
- Release validation pinned to the project virtual environment so clean macOS/Homebrew installs cannot bypass test dependencies.

### Compatibility

- `catalyst-data-record/1.0` and every existing v1/v2 exchange contract remain unchanged.
- SQLite behavior and migration history remain supported through migration 014.
- SQLite verified file backup/restore remains unchanged.
- PostgreSQL backup and point-in-time recovery are intentionally delegated to the managed database provider.
- PostGIS is not enabled automatically; v2.1.0 only establishes a clean extension-capable PostgreSQL foundation.
